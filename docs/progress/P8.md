- Pure rules: `lib/share/codes.ts` (generate, format, normalise, plausible, hash), `evaluate.ts` (valid/expired/revoked), `ratelimit.ts` (isRateLimited, clientIp, hashIp), `filter.ts` (hidden filter), `session.ts` (token, cookie, `resolveViewer`), `summary.ts` (`buildSummary`), `lib/audit-labels.ts` (`describeLogEntry`).

## Tests
`tests/share.test.ts` (53): 10,000 distinct valid codes, alphabet, normalisation, hash depends on pepper and is never the code, the four share states with injected clocks, rate limit at the fifth failure, expiry limits, hidden filter (category, document, no-document fact, removed, superseded, hiddenAny), session lifetime capped at share expiry, revoke/expiry stop a session on the next call, summary groups and hidden-never-leaks, labels. `tests/architecture.test.ts` extended to cover the new pure modules. Whole suite: 376 passing.

## Verified live (smoke, 69 checks, run twice, dev server + real database)
Unknown, expired and revoked codes give byte-identical 403 bodies; sloppy typing of the right code opens it; cookie flags; open response has no record content; only a 64-hex hash stored; summary hides the tagged fact and shows the partial notice; hidden fact image is 404, visible one 302, no cookie 403, other-record fact 404; access log shows create, open, image view, refused attempts with reason; revoke is idempotent and the next request is `share_revoked`; cookie lifetime at most the share lifetime; 5 wrong codes then 429 even for the correct code, other IP unaffected; limits (under 15 min, over 24 h, referral without referral, unknown category) are 400.

## Deviations (see DEVIATIONS.md D-016)
- The layout differs from the prompt's file list to keep database code out of pure files (separation of concerns): DB functions of `ratelimit.ts` live in `queries.ts`; `session.ts` holds the pure parts and `getViewerFromRequest` lives in `service.ts`; `getViewerSummary` is in `service.ts` and delegates to the pure `buildSummary`.
- A referral share requires a `referral_id` (the prompt listed it as optional).
- `viewer_open_refused` log entries carry the name and practice number the person typed, so the patient can see who tried a dead code.
