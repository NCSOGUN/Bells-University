# P10: hospital link, partner feed, simulated hospital (C14, C15, C16)

FR-25, FR-26, FR-27, NFR-22, NFR-23, NFR-24.

## Built
- `lib/feed/fhir-subset.ts`: Zod schemas for the FHIR R4-aligned subset (L29). `parseBundle(json)` returns `{ok, patient:{linkRef, hospitalPatientRef}, observations, serviceRequests}` or `{ok:false, issues:[{path,message}]}`. Exactly one Patient, at most 50 entries, only Observation and ServiceRequest, unknown fields stripped. Issues never echo values.
- `lib/feed/map.ts`: `observationToFact` and `serviceRequestToFact` (L21, L27, L28).
  - Facts are provider_entered and confirmed, with the hospital, facility name and receipt.
  - `source_identifier` is `"<system>|<value>"`; test_key comes from the glossary.
  - Dates keep the date part only; numbers come from our parsers.
  - Referral reason, urgency and requester are carried verbatim, or null.
- `lib/feed/intake.ts`: `processFeedRequest(request, deps)` with injected deps, in the L26 order (405, 401, 400, 413, 415, 422, 403, 200 replay, 202).
  - The link decision goes through `can(partner, "write_feed")`.
  - Unknown, revoked, other-hospital and changed-patient links all get one identical 403 body.
  - A concurrent duplicate key gets the replay response.
- `lib/feed/queries.ts` and `service.ts`: one transaction per accepted delivery. It:
  - re-checks the link `FOR UPDATE`
  - writes the receipt first, then the facts, with a `fact_event` per fact
  - supersedes older facts and writes a `superseded` event on each one
  - sets `hospital_patient_ref` on the first delivery
  - writes `feed_delivery_accepted` to the access log
  
  Refusals write a receipt with no idempotency key. When the link existed they also write `feed_delivery_refused` on the record.
- Routes, all in `docs/api.md` with the feed contract, an example bundle, curl, the refusals table and the L28 limitation:
  - `POST /api/feed/v1/bundles` (other methods 405 `Allow: POST`)
  - `app/api/feed/[[...path]]` (every method 405)
  - `GET /api/hospitals`
  - `POST /api/links` and `POST /api/links/{id}/revoke`
  - `GET /api/records/{id}/links`
- `lib/links/`:
  - Create: link_ref `ITN-LNK-` plus 8 L9 characters, a QR of the ref, and a `link_created` log entry.
  - Revoke: idempotent, logs `link_revoked` once.
  - List: accepted and refused counts, and the last delivery time.
- `tools/sim-hospital/` (C16, SIMULATED):
  - `cli.ts`: `npm run sim -- send-results | send-referral | correct-result | refusals`. It prints the banner on every run and imports nothing from lib/ or app/.
  - Fixtures: `results.json` (haemoglobin and fasting glucose as valueString, creatinine as valueQuantity), `referral.json` and `README.md`.
- Tests: `tests/feed.test.ts` (46). They cover:
  - every refusal row, with the four link failures byte-identical
  - a replay writes nothing; a concurrent duplicate; a revoke mid-write
  - refusal logging per case, and no idempotency key on refusals
  - mapping: valueString exact, valueQuantity with its unit, ranges, dates, referral verbatim
  - invalid bundles: two Patients, MedicationRequest, 51 entries, wrong link system, no hospital number
  - no record content in any refusal body; the fixtures validate
  - route exports are only POST, the 405 handlers and `runtime`; every method is 405 on the catch-all
  - no feed module imports fact, share or referral code; the CLI imports nothing from lib/ or app/
  
  The feed's pure files are added to the architecture test. Whole suite: 469 passing; typecheck and lint clean.

## Verified live (13 Nov, dev server, Supabase London)
- `npm run sim -- refusals --link ITN-LNK-MZX36QMW --mrn DEMO-00123 --revoked-link ITN-LNK-VQWFJEDR` gave **ALL PASS** on 14 checks:
  - GET, PUT and DELETE 405; the probe path 405
  - wrong key and no key 401
  - unlinked 403 and revoked 403, with byte-identical bodies
  - MedicationRequest 422; 1.2 MB body 413; missing key 400
  - the same key gave 202, then 200 with the same receipt_id
- `send-results`, then `GET /api/records/{id}/facts`: haemoglobin, fasting blood glucose and creatinine appear as provider_entered and confirmed, from "Demo General Hospital (SIMULATED)", dated 2026-11-10.
- `send-referral`: a referral fact with the reason, `urgent` and the requester carried verbatim.
- `correct-result`: haemoglobin 11.6 is current; the 11.2 rows are kept and superseded.
- Revoking the link and sending again gave 403 `link_not_active`.
  - The access log showed "You unlinked …", then "A delivery from Demo General Hospital (SIMULATED) was refused".
  - `GET /api/records/{id}/links` showed the counts.
- Anonymous calls to `/api/hospitals`, `/api/links` and `/api/records/{id}/links` gave 401.
